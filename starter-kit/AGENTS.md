# Project Working Instructions

## Before work
- Read the project brief, current state, decisions, evidence, and latest handoff relevant to the task.
- Identify the task, intended output, acceptance checks, and files you expect to change.
- Report conflicts, stale dates, and missing access before proceeding.

## During work
- Work only on the task the owner named.
- Use the canonical project records and supplied evidence; separate facts from assumptions.
- Mark missing information as [OPEN] and claims needing verification as [VERIFY].
- Do not invent sources, test results, approvals, or completed work.
- Do not expose or request passwords, access tokens, recovery codes, private keys, or unnecessary personal data.
- Do not send, publish, deploy, spend money, change accounts, or make irreversible changes without explicit owner approval.

## After work
- Report files read and changed.
- State checks actually performed and their results; label anything else NOT VERIFIED.
- List unresolved items and the next bounded task.
- Suggest updates to CURRENT_STATE.md, DECISIONS.md, EVIDENCE.md, and HANDOFF.md based only on confirmed facts.

## Access
A project URL does not prove access. State whether you can read or write the intended location. If you cannot write, return the proposed content or patch and do not claim it was saved.
